=== SLIDE 14 ===
The web interface enables users to log in, manage their profiles, and enter travel preferences or past trips. 

User credentials are verified through an authentication API, and valid users receive secure access tokens. 

Input data is validated and stored across PostgreSQL, MongoDB, and Firebase databases for structured, semi-structured, and real-time data. 

When needed, the system fetches the combined user profile from these databases and passes it to the personalization model to generate tailored heritage site recommendations.


=== SLIDE 15 ===
The personalization module uses user queries and preferences to process input and apply collaborative filtering with SVD decomposition. 

It extracts latent features and generates candidate heritage sites. RoBERTa or DistilBERT models create embeddings to measure contextual similarity. 

A score fusion layer combines similarity and collaborative scores to produce a ranked list of heritage site recommendations, which is then sent to the sustainability model for final evaluation and personalized travel suggestions.

=== SLIDE 16 ===
The sustainability module evaluates ranked heritage sites using extracted features like size and distance. 

Multiple linear regression predicts each site’s impact, which is then analyzed using the TOPSIS multi-criteria decision-making method.
 
This process generates sustainability scores that measure environmental and social effects. 

The final sustainability scores are passed to the itinerary optimization model to ensure travel plans promote eco-friendly and balanced tourism choices.

=== SLIDE 17 ===
This flow shows how the system creates an optimized travel plan. First, heritage sites are ranked based on distance and sustainability.

 These sites form a graph where travel paths are tested using the Ant Colony Algorithm. 

The algorithm repeatedly finds better routes by updating “pheromone” levels, similar to how ants find the shortest path. 

Finally, it selects the route with the least distance and highest sustainability, generating the best possible itinerary in JSON format.

=== SLIDE 18 ===
The Planner Agent acts as the central coordinator, combining insights from the Personalization, Sustainability, and Itinerary Optimization models.

 It collects user data and preferences through the Web Interface, integrates ranked recommendations, sustainability scores, and optimized routes, and generates the final customized travel plan.

By orchestrating data from all modules, the Planner Agent ensures that the final itinerary is not only personalized and efficient but also environmentally sustainable and aligned with user expectations.
